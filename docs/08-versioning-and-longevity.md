# 08 · Versioning and Longevity

*Layer: Core.*

Most AI skills frameworks age within two years because they describe today's techniques. HACF separates what changes slowly from what changes fast.

## Three layers

| Layer | Contains | Expected change rate | Versioning |
|---|---|---|---|
| **Core** | Principles, level names and definitions, interaction modes, five dimensions, gate logic, evidence logic | Decades | MAJOR (x.0.0) |
| **Indicators** | 0–5 descriptors, gate thresholds, behavioural indicators, metrics, question bank, tasks | Reviewed every 12 months | MINOR (0.x.0) |
| **Examples** | Tools, products, role profiles, regulatory mapping, crosswalks | Any time | PATCH (0.0.x) |

Every document states its layer at the top.

## Why the Core should survive the next decades

The core is built on relationships that hold regardless of how capable AI becomes:

| As AI evolves… | …what changes for people | HACF already covers it via |
|---|---|---|
| Assistants → copilots | More collaboration, less typing | Mode *Collaborate* (L3) |
| Copilots → agents | Work is delegated, not done | Mode *Delegate & Orchestrate* (L4), J4 |
| Agents → autonomous systems | Oversight and accountability dominate | Mode *Govern* (L5), J and R gates |
| AI embedded everywhere, invisible | Awareness of hidden AI becomes basic safety | L0 risk note, L1 |
| Regulation matures | Accountability formalised | R dimension, regulatory mapping layer |

If AI one day performs most building itself, *Creation* shifts from "construct" to "specify, test and accept" — still captured by C3–C5 descriptors, which are about reliability and control, not coding.

## Review cycle

- **Annual indicator review** each Q1: descriptors, thresholds, question bank, tasks — informed by pilot data.
- **Examples** updated continuously via pull requests.
- **Major revision** only when evidence shows the core no longer discriminates well (e.g. most people cluster at one level, or levels stop predicting outcomes).
